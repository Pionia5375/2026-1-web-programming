# PlanIt — 7분 발표 대본

> 한 줄 ≈ 한 호흡. 또박또박 읽어 **6:50 ~ 7:10** 사이.
> `((  ))` 안은 화면 지시. 슬라이드 매핑은 맨 아래 부록.

---

### [0:00] 인사

안녕하세요.
컴퓨터공학부 202100580 이정입니다.
이번 학기 웹 프로그래밍 기말 프로젝트, **PlanIt** 을 발표하겠습니다.

### [0:10] 왜 만들었는가

대학생이 매일 다루는 일정은 크게 두 가지입니다.
강의·미팅·시험처럼 **시각이 정해진 일정**,
그리고 과제·보고서처럼 **마감일이 있는 작업** 입니다.

문제는, 시중의 도구들은 캘린더 앱과 투두 앱이 분리되어 있다는 점입니다.
PlanIt 은 이 두 가지를 **하나의 데이터 모델로 추상화** 해서, **한 화면에 모은 서비스** 입니다.

### [0:40] 핵심 기능

핵심 기능은 여섯 가지입니다.
bcrypt 와 JWT 기반 인증,
우선순위가 있는 할 일, 시간과 장소가 있는 일정,
월·주·일·아젠다 네 가지 뷰의 통합 캘린더,
오늘 마감과 오늘 일정을 한 번에 보여 주는 대시보드,
그리고 다크 모드와 마감 1시간 전 브라우저 알림까지 갖췄습니다.

### [1:05] 전체 아키텍처

전체 구조를 짚어 보겠습니다.
브라우저에서 접속하면, 먼저 **Vercel** 이 React 정적 자원을 곧바로 응답합니다.
`/api` 로 시작하는 요청만 **Render 위의 Docker 컨테이너** 로 가서,
Express 와 Prisma 가 처리합니다.
데이터는 **Neon Postgres** 에 영속되고, 응답은 **IndexedDB** 에 캐시되어,
네트워크가 끊겨도 마지막 데이터를 보여 줄 수 있습니다.

### [1:40] 기술 스택

기술 스택은 수업에서 다룬 요소를 그대로 채택했습니다.
프런트엔드는 React · Vite · Tailwind,
백엔드는 Express · Prisma · JWT · zod,
운영은 PostgreSQL · Docker · Nginx · GitHub Actions 입니다.

### [2:00] 조건 ① — DBMS 활용

이제 제출 조건 세 가지가 어떻게 적용되었는지 차례로 설명드리겠습니다.
먼저, **DBMS 활용** 부분입니다.

사용자와 할 일, 사용자와 일정은 모두 **1대 다 관계** 이기 때문에,
관계형 모델이 가장 자연스러웠습니다.
스키마는 **Prisma** 로 우선 정의했고, 마이그레이션 파일은 그대로 운영에 적용됩니다.
복합 인덱스를 걸어 캘린더 범위 쿼리를 가속했고,
운영 DB 는 **Neon 의 서버리스 Postgres** 를 SSL 강제로 연결했습니다.

### [2:30] 조건 ② — Web Storage 활용

같은 조건의 두 번째, **Web Storage 활용** 입니다.
저장소를 단순히 같이 쓰는 게 아니라,
**데이터의 수명과 범위에 따라 네 계층으로 나누어** 사용했습니다.

영속 데이터의 본체는 PostgreSQL,
토큰과 테마처럼 영구히 유지할 사용자 설정은 **localStorage**,
검색어와 마지막 본 월처럼 탭 단위 상태는 **sessionStorage**,
오프라인 폴백을 위한 캐시는 **IndexedDB** 에 두었습니다.

이렇게 각 데이터의 수명과 범위가 명확하도록 분담했습니다.

### [3:05] 조건 ③ — Docker

다음 조건, **Docker** 부분입니다.
`docker compose up` 한 번이면 **web, api, db 세 컨테이너** 가 동시에 뜹니다.
`pg_isready` 헬스체크가 통과해야 api 가 부팅되도록 의존성을 걸었고,
이미지는 **multi-stage build** 로 런타임을 슬림하게 줄였습니다.

베이스를 **node:20-slim** 으로 잡은 것은,
Prisma 가 Alpine 의 OpenSSL 을 잘못 감지하는 이슈를 피하기 위한 결정이었습니다.

### [3:40] 조건 ③ — Nginx 리버스 프록시

같은 조건의 **Nginx** 부분입니다.
웹 컨테이너의 Nginx 가 `/api` 요청은 백엔드로 리버스 프록시하고,
그 외 요청은 React 빌드 산출물을 직접 응답합니다.

이 구성으로 **CORS 가 불필요** 해지고,
gzip 으로 자바스크립트 번들이 138 킬로바이트까지 줄어들고,
정적 자산에 1년 immutable 캐시를 두어 재방문 시 다운로드가 0 바이트가 됩니다.
SPA 새로고침 200 응답도 보장됩니다.

### [4:10] 조건 ④ — CI/CD 자동 배포

마지막 조건, **CI/CD 자동 배포** 입니다.
main 으로 push 가 들어오면 **세 가지 자동화가 동시에** 트리거됩니다.

첫째, **GitHub Actions 의 ci.yml** 이 server, client, docker compose 빌드를 모두 검증합니다.
둘째, **Vercel 의 GitHub 연동** 이 프런트엔드를 자동으로 Edge 배포합니다.
셋째, **Render 의 autoDeploy** 옵션이 백엔드 Docker 이미지를 빌드하고,
마이그레이션까지 자동으로 적용합니다.

실제로 이 프로젝트는 여러 개의 PR 을 머지하며 **무중단으로 운영에 반영** 되었습니다.

### [4:50] 보안 · 안정성 · UX

마지막 기술 마무리로,
bcrypt, JWT, zod 로 인증과 입력을 보호했고,
axios 인터셉터로 401 응답 시 자동 로그아웃이 동작합니다.
CORS 화이트리스트와 오프라인 캐시, OS 다크 모드 감지까지 더해 사용자 경험을 다듬었습니다.

### [5:10] 라이브 시연  ((브라우저로 화면 전환))

이제 실제 배포된 사이트에서 한 사이클 보여 드리겠습니다.

먼저 로그인합니다.
대시보드에는 오늘 마감 할 일과 오늘 일정이 자동으로 표시됩니다.

새로운 할 일을 추가해 보겠습니다.
제목 "보고서 작성", 우선순위 상, 마감일은 오늘 자정으로 등록합니다.
검색창에 단어를 입력하면 필터가 즉시 적용됩니다.
이 검색어는 sessionStorage 에 저장돼서, 다른 페이지에 갔다가 돌아와도 그대로 유지됩니다.

이번엔 일정을 추가합니다.
제목 "수업", 장소 "공학관", 10시부터 11시 30분으로 등록합니다.
종료가 시작보다 빠르면 서버가 zod 유효성으로 막아 줍니다.

캘린더 화면으로 이동합니다.
같은 월 안에 일정은 파란색, 미완료 할 일은 노란색으로 함께 표시됩니다.
월, 주, 일, 아젠다 네 가지 뷰를 전환할 수 있고, 모두 한국어 로케일로 표시됩니다.

다크 모드를 켭니다.
새로고침해도 그대로 유지되는데, localStorage 에 저장돼 있기 때문입니다.

대시보드로 돌아오면,
미리 등록해 둔 마감 한 시간 이내의 할 일에 대해 브라우저 알림이 뜹니다.
Notification API 를 사용했고, 이미 알린 항목은 localStorage 에 기록해 중복을 막았습니다.

마지막으로, 개발자 도구의 Application 탭에서 IndexedDB 를 열어 보면,
`planit-cache` 라는 저장소에 할 일과 일정이 캐시되어 있습니다.
이것이 네트워크 장애 시 폴백 데이터로 쓰입니다.

### [6:40] 마무리  ((마무리 슬라이드로 복귀))

정리하면, PlanIt 은 14주차 설계서를 그대로 구현해,
**GitHub Actions CI/CD · Docker · Nginx · Web Storage · DBMS**,
다섯 가지 조건을 모두 적용한 풀스택 프로젝트입니다.

서비스 URL 과 GitHub 저장소는 슬라이드에 표시되어 있습니다.
한 학기 동안 좋은 강의 감사드립니다.
이상으로 발표를 마치겠습니다.

**감사합니다.**

## 6. DBMS 활용 · 2:00 → 2:30 (30초)  ─ 조건 ③

> 슬라이드 6.

"제출 조건 중 첫 번째, DBMS 활용 부분입니다.

사용자와 할 일, 사용자와 일정은 모두 **1대 다 관계** 이기 때문에,

관계형 모델이 가장 자연스러웠습니다.

스키마는 **Prisma** 로 우선 정의하고, 마이그레이션 파일은 그대로 운영에 적용됩니다.

복합 인덱스를 걸어 캘린더 범위 쿼리를 가속했고,

운영 DB 는 Neon 의 서버리스 Postgres 를 SSL 강제로 연결했습니다."

---

## 7. Web Storage 활용 · 2:30 → 3:05 (35초)  ─ 조건 ③

> 슬라이드 7.

"같은 조건의 두 번째, Web Storage 활용입니다.

저장소를 단순히 같이 쓰는 게 아니라,

**데이터의 수명과 범위에 따라 네 계층으로 나누어** 사용했습니다.

영속 데이터의 본체는 PostgreSQL,

토큰과 테마처럼 영구히 유지할 사용자 설정은 **localStorage**,

검색어와 마지막 본 월처럼 탭 단위 상태는 **sessionStorage**,

오프라인 폴백을 위한 캐시는 **IndexedDB** 에 두었습니다.

각 저장소가 실제로 어떤 코드에서 쓰이는지 슬라이드 하단에 정리해 두었습니다."

---

## 8. Docker · 3:05 → 3:40 (35초)  ─ 조건 ②

> 슬라이드 8.

"두 번째 조건, Docker 부분입니다.

`docker compose up` 한 번이면 **web · api · db 세 컨테이너** 가 동시에 뜹니다.

`pg_isready` 헬스체크가 통과해야 api 가 부팅되도록 의존성을 걸었습니다.

이미지는 **multi-stage build** 로 런타임을 슬림하게 줄였고,

베이스를 **node:20-slim** 으로 잡은 것은,

Prisma 가 Alpine 의 OpenSSL 을 잘못 감지하는 이슈를 피하기 위한 결정이었습니다."

---

## 9. Nginx 리버스 프록시 · 3:40 → 4:10 (30초)  ─ 조건 ②

> 슬라이드 9.

"같은 조건의 Nginx 부분입니다.

웹 컨테이너의 Nginx 가 `/api` 요청은 백엔드로 리버스 프록시하고,

그 외 요청은 React 빌드 산출물을 직접 응답합니다.

이 구성 한 가지로 **CORS 가 불필요** 해지고,

gzip 으로 JS 가 138 KB 까지 줄어들고,

`/assets` 의 1년 immutable 캐시로 재방문 시 자산이 0 바이트가 됩니다.

SPA 새로고침 200 응답도 보장됩니다."

---

## 10. CI/CD 자동 배포 · 4:10 → 4:50 (40초)  ─ 조건 ①

> 슬라이드 10.

"세 번째 조건, CI/CD 자동 배포입니다.

main 으로 push 가 들어오면 **세 가지 자동화가 동시에** 트리거됩니다.

첫째, GitHub Actions 의 `ci.yml` 이 server · client · docker compose 빌드를 모두 검증합니다.

둘째, Vercel 의 GitHub 연동이 프런트엔드를 자동으로 Edge 배포합니다.

셋째, Render 의 autoDeploy 옵션이 백엔드 Docker 이미지를 빌드하고,

마이그레이션까지 자동으로 적용합니다.

실제로 이 프로젝트는 다섯 개의 PR 을 머지하며 **무중단으로 운영에 반영** 되었습니다."

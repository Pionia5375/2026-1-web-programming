## ⑥ 조건 ③ — DBMS 활용  ─  2:00 → 2:30  (30초)

> 화면 — 슬라이드 6 (Prisma 스키마 + 운영 포인트).

"제출 조건 중 첫 번째로, DBMS 활용 부분입니다.

User 와 Task, User 와 Event 가 모두 **1:N 관계** 이기 때문에 관계형 모델이 가장 자연스러웠고,

**Prisma** 로 스키마 우선 개발했습니다. 마이그레이션 파일은 그대로 운영에 `prisma migrate deploy` 로 적용됩니다.

`@@index` 로 사용자 + 마감/시작 시각 복합 인덱스를 걸어 캘린더 범위 쿼리를 가속하고,

운영 DB 는 **Neon 의 서버리스 Postgres** 를 SSL 강제로 연결했습니다."

---

## ⑦ 조건 ③ — Web Storage 활용  ─  2:30 → 3:05  (35초)

> 화면 — 슬라이드 7 (4계층 표 + 코드 파일).

"같은 조건의 두 번째, Web Storage 활용입니다.

저장소를 단순히 같이 쓰는 게 아니라 **데이터의 수명과 범위에 따라 4계층으로 분담** 했습니다.

영속 + 다기기 일관성이 필요한 본체는 PostgreSQL,

토큰과 테마처럼 영구히 유지할 사용자 설정은 **localStorage**,

검색어와 마지막 본 월처럼 탭 단위로만 필요한 상태는 **sessionStorage**,

오프라인 폴백을 위한 캐시는 **IndexedDB** 에 두었습니다.

각각이 실제로 어떤 파일에서 사용되는지 슬라이드 하단에 정리해 두었습니다."

---

## ⑧ 조건 ② — Docker  ─  3:05 → 3:40  (35초)

> 화면 — 슬라이드 8 (3 컨테이너 다이어그램 + 기술 포인트).

"두 번째 조건, Docker 부분입니다.

`docker compose up` 한 번에 **web, api, db 세 컨테이너** 가 동시에 뜹니다.

`pg_isready` 헬스체크가 통과해야 api 가 부팅되도록 의존성을 걸었고,

이미지는 **multi-stage build** 로 빌드 산출물만 런타임 이미지에 남깁니다.

베이스를 **node:20-slim** 으로 잡고 `binaryTargets` 를 명시한 것은,

Prisma 가 Alpine 의 OpenSSL 버전을 잘못 감지하는 알려진 이슈를 회피하기 위한 결정이었습니다."

---

## ⑨ 조건 ② — Nginx 리버스 프록시  ─  3:40 → 4:10  (30초)

> 화면 — 슬라이드 9 (nginx.conf 코드 + 효과).

"같은 조건의 Nginx 부분입니다.

웹 컨테이너의 Nginx 가 `/api` 로 들어오는 요청은 Express 로 리버스 프록시하고,

나머지는 React 빌드 산출물을 직접 응답합니다.

이 한 가지로 **CORS 가 불필요** 해지고, gzip 으로 JS 가 138 KB 까지 줄어들고,

`/assets` 에 1년 immutable 캐시를 박아서 재방문 시 자산을 0 byte 로 만들었습니다.

또 `try_files ... /index.html` 로 SPA 새로고침 200 응답까지 보장됩니다."

## ⑩ 조건 ① — CI/CD 자동 배포  ─  4:10 → 4:50  (40초)

> 화면 — 슬라이드 10 (3 박스 흐름 + ci.yml 작업).

"세 번째 조건, CI/CD 자동 배포 부분입니다.

main 으로 push 가 들어오면 **세 가지 자동화가 동시에** 트리거됩니다.

첫째, GitHub Actions 의 `ci.yml` 이 server / client / docker compose 빌드를 모두 검증합니다.

둘째, **Vercel GitHub 연동** 이 client 디렉토리를 자동 감지해서 Edge 글로벌 배포까지 30 초 안에 끝냅니다.

셋째, **Render 의 autoDeploy** 옵션이 server/Dockerfile 을 빌드하고 마이그레이션까지 자동 적용합니다.

이 프로젝트는 실제로 4개의 PR 을 머지하며 **무중단으로 운영에 반영** 되었습니다."

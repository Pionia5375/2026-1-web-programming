이번 학기 웹 프로그래밍 기말 프로젝트로 만든 서비스는 **PlanIt** 입니다.

PlanIt 은 **할 일과 일정을 한 화면에서 통합 관리**하는 개인용 웹 서비스이고,

오늘 발표에서는 서비스 소개와 주요 기능 시연, 그리고 적용한 기술을 7분 안에 보여드리겠습니다."

## 🎬 0:30 – 1:15  만든 이유 + 사용자  (≈45초)

> 화면 — 슬라이드 그대로.

"왜 만들었는지 먼저 말씀드리면,

대학생 입장에서 매일 다루는 일정은 크게 두 종류입니다.

하나는 강의, 미팅, 시험처럼 **시각이 정해진 일정(Event)**,

다른 하나는 과제, 보고서처럼 **마감일이 있는 할 일(Task)** 입니다.

기존 도구들은 캘린더 앱과 투두 앱이 분리되어 있어서, 두 앱을 번갈아 보는 불편함이 있습니다.

PlanIt 은 이 두 영역을 **단일 인터페이스** 에서 함께 보여 주는 데 초점을 맞췄습니다.

주된 사용자는 학사 일정을 함께 관리해야 하는 **대학생** 으로 설정했고, 구조를 단순하게 유지해서 일반 사용자도 그대로 쓸 수 있게 했습니다."

---

## 🎬 1:15 – 1:45  기술 스택 한눈에  (≈30초)

> 화면 — 슬라이드의 "기술 스택" 섹션 가리킴. 또는 README 디렉토리 트리.

"기술 스택은 수업에서 다룬 요소를 그대로 활용했습니다.

프런트엔드는 **React + Vite + Tailwind**, 캘린더 UI 는 **react-big-calendar** 를 썼고,

백엔드는 **Express + Prisma + PostgreSQL**, 인증은 **bcrypt 와 JWT** 로 처리했습니다.

운영 환경에서는 **Docker Compose** 로 데이터베이스, API, 웹 세 컨테이너가 동시에 뜨고,

그 앞에 **Nginx** 를 리버스 프록시로 두어 정적 자원과 API 요청을 같은 출처에서 서비스합니다."

## 🎬 1:45 – 4:00  핵심 기능 시연  (≈135초, 가장 큰 비중)

> 화면 — 라이브 사이트 `https://client-eight-ivory-60.vercel.app` 접속.
> 사전에 회원가입 한 계정으로 로그인 (또는 시연 중 회원가입).

"이제 실제 배포된 서비스에서 시연해 보겠습니다."

### (1) 로그인 / 대시보드 — 약 25초

> 로그인 화면.

"먼저 이메일과 비밀번호로 로그인합니다.

비밀번호는 서버에서 **bcrypt 로 해시 처리**되어 저장되고, 로그인이 성공하면 **JWT 토큰**이 발급됩니다.

이 토큰은 브라우저 **localStorage** 에 저장되어, 다음에 접속할 때도 로그인 상태가 유지됩니다."

> 로그인 → 대시보드 진입.

"대시보드에는 **오늘 마감인 할 일** 과 **오늘 일정** 이 자동으로 표시됩니다.

학기 중에 가장 자주 보게 될 화면을 메인으로 둔 거고요."

### (2) 할 일 — 약 25초

> 좌측 상단 "할 일" 클릭.

"할 일 화면에서는 **제목, 설명, 마감일, 우선순위 상·중·하** 를 지정해서 등록할 수 있습니다."

> "새 할 일" 클릭 → 제목 "보고서 작성", 우선순위 상, 마감 입력 → 저장.

"등록한 항목은 우선순위에 따라 색이 다르게 표시되고, 체크박스로 완료 처리가 가능합니다."

> 검색창에 단어 입력.

"제목 검색과 우선순위 필터도 됩니다.

검색어는 **sessionStorage** 에 저장되기 때문에, 다른 페이지에 갔다가 돌아와도 그대로 유지됩니다."

### (3) 일정 — 약 20초

> "일정" 클릭 → 새 일정 추가.

"일정은 시작 시각, 종료 시각, 장소를 입력해서 등록합니다.

종료가 시작보다 빠르면 서버의 **Zod 유효성 검사**가 막아 줍니다."

### (4) 통합 캘린더 — 약 35초

> "캘린더" 클릭.

"가장 핵심이 되는 통합 캘린더 화면입니다.

같은 월 뷰 안에 **일정은 파란색, 미완료 할 일은 노란색, 완료된 할 일은 회색** 으로 한 번에 보입니다."

> 월/주/일/아젠다 탭 차례로 클릭.

"월, 주, 일, 아젠다 네 가지 뷰를 지원하고, 한국어 로케일을 적용해서 요일과 안내 문구가 모두 한글로 표시됩니다.

마지막으로 본 월은 **sessionStorage** 에 저장되어, 새로고침해도 같은 달이 그대로 열립니다."

### (5) 다크 모드 + 알림 — 약 30초

> 우상단 다크 모드 버튼 토글.

"다크 모드를 지원하고, 선택한 테마는 **localStorage** 에 저장되어서 다음 접속 시에도 유지됩니다."

> 미리 등록해 둔 1시간 이내 마감 할 일이 있는 상태로 대시보드로 이동.

"또 한 가지, 마감 한 시간 전이 되면 **브라우저 Notification API** 로 자동 알림이 뜹니다.

이미 알림을 보낸 항목은 localStorage 에 기록해서 중복 알림을 막았습니다."

## 🎬 4:00 – 5:30  설계 포인트 — Web Storage / DBMS 역할 분담  (≈90초)

> 화면 — README 의 "Web Storage / DBMS 역할" 표 또는 슬라이드.

"제출 요건에 Web Storage 와 DBMS 활용이 있어서, 두 가지를 단순히 같이 쓰는 게 아니라 **역할을 명확히 나눠서** 설계했습니다."

1. "**PostgreSQL** 은 사용자, 할 일, 일정처럼 영속적으로 보관해야 하고 여러 디바이스 간에 일관성이 필요한 데이터를 저장합니다. 호스팅은 무료 플랜을 제공하는 **Neon Postgres** 를 사용했습니다."

2. "**localStorage** 는 로그인 토큰과 다크 모드 설정처럼 **영구적으로 유지되어야 하는 사용자 설정** 을 저장합니다."

3. "**sessionStorage** 는 검색어와 마지막으로 본 월처럼 **현재 탭에서만 의미가 있는 임시 상태** 를 저장합니다."

4. "**IndexedDB** 는 할 일과 일정의 **로컬 캐시** 로 활용합니다. 네트워크가 끊긴 상태에서 페이지를 열어도 마지막으로 가져온 데이터를 보여 줄 수 있습니다."

> DevTools → Application → IndexedDB → planit-cache 보여 주기 (시간 되면).

"이렇게 네 가지 저장소를 성격에 맞게 분담해서, 각 데이터의 **수명과 범위** 가 명확하도록 구성했습니다."

## 🎬 5:30 – 6:30  Docker · Nginx · CI/CD 구성  (≈60초)

> 화면 — README 의 "디렉토리 구조" 또는 `.github/workflows/ci.yml`.

"운영 환경 구성도 수업 내용 그대로 따랐습니다.

로컬에서는 `docker compose up` 한 번이면 **데이터베이스, API, 웹 세 컨테이너** 가 동시에 뜹니다.

웹 컨테이너에서 **Nginx** 가 `/api` 로 들어오는 요청은 백엔드로 리버스 프록시하고, 그 외 요청은 React 빌드 산출물을 직접 응답합니다.

**gzip 압축, 정적 자원의 immutable 캐시, SPA fallback** 까지 모두 설정했습니다.

배포는 **GitHub Actions** 기반 CI/CD 로 자동화했습니다.

- main 브랜치에 push 가 들어오면 `ci.yml` 이 server 와 client 의 빌드, 그리고 docker compose 빌드를 모두 검증합니다.

- **프런트엔드는 Vercel 의 GitHub 연동** 으로 자동 배포되고, **백엔드는 Render 의 autoDeploy** 옵션으로 같은 push 에 자동으로 빌드·배포됩니다."
